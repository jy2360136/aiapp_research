# 调研与缺陷排查方法

## 单页证据包

每个页面至少记录以下证据：

1. 页面截图；
2. UIAutomator 界面树；
3. 当前前台 Activity / Window；
4. 从首页到该页的点击路径；
5. 返回路径与返回后的落点；
6. 点击前后的异常日志时间窗；
7. 文案、按钮、状态、空态、加载态、错误态观察。

## 页面地图遍历

采用受控深度优先遍历，而不是无边界随机点击：

- 以首页为根节点，按顶部页签、侧边栏、二级功能入口逐层展开；
- 每次进入页面后先截图和导出结构，再决定是否继续点击；
- 每步只点击一个可识别元素，并记录其文本/描述/坐标；
- 返回后校验页面签名，确认是否回到预期父页面；
- 对动态行情、WebView、视频、悬浮广告等不稳定区域单独标注；
- 以“可复现路径 + 预期行为 + 实际行为 + 证据”登记问题。

## 安全黑名单

自动遍历不得点击或提交：买入、卖出、撤单、银证转账、退出登录、删除、支付、开户、风险测评提交、修改密码，以及任何需要确认资金或身份的操作。

## 日志可获取性

本项目设备上的掌小宝为 `DEBUGGABLE` 安装包，因此可通过 ADB 获取其进程日志；普通非调试安装包通常仍能看到系统级崩溃/ANR 相关日志，但应用私有日志覆盖程度取决于系统策略。仓库只提交经筛选和脱敏的异常证据。


## 版本化与截图目的

- 开始测试前先记录包名和版本号。
- 掌小宝截图目录：`research/target-dongzheng-ai/screenshots/v<版本>_<日期>/`。
- 一级功能分区：`01-盯盘`、`02-对话`、`03-自选`、`04-交易`、`05-设置与协议`。
- 竞品截图目录：`research/competitors/<产品>/v<版本>_<日期>/screenshots/`。
- 每张截图必须有验证目的，按 `stepNN_操作_结果.png` 命名。
- 每个版本和功能分区都要有 README，写清当前进度、结论、剩余问题和下一轮入口。
- 新版本修复旧问题后，旧版本截图仅作为回归对照，不混入新版本目录。
- UI 树、截图和日志必须同步骤对应，避免只留截图无法解释结论。
