## DEF-001：AI 首次查询间歇性返回“服务开小差了”

### 前置条件

1. 掌小宝已安装并可正常访问网络。
2. 不要求登录交易账户；使用公开行情问答即可。
3. 测试前不要清空系统网络缓存，保持与普通用户首次打开一致的场景。

### 复现步骤

1. 从系统最近任务中彻底划掉掌小宝，或执行 `adb shell am force-stop dongzheng.ai.android.phone`。
2. 冷启动 App，等待首页骨架屏结束。
3. 点击顶部「对话」。
4. 点击底部「提问或搜索」输入框。
5. 输入 `600519`，点击发送。
6. 观察回复区 1–30 秒。
7. 如果出现错误，完全退出并重新启动 App，再次重复第 3–5 步。

### 预期结果

- 返回贵州茅台行情、K 线、文字结论和数据来源；或返回带错误码、重试按钮、请求 ID 的结构化错误页。
- 错误不应只显示一句“服务开小差了，请稍后再试”而丢失请求上下文。

### 实际结果

- 曾在冷启动后的首次 `600519` 查询中返回“服务开小差了，请稍后再试”。
- 同一问题在退出并冷启动后重试，可正常返回行情、日 K、结论和“来源”卡片。
- 因此当前证据更支持“首次请求/网关/流式链路间歇失败”，尚不能判定为模型能力问题。
- 2026-11-18 12:26–12:29 追加 5 次冷启动 `600519` 首问，5/5 均成功返回，说明复现概率不高，不能仅凭单次失败判断全量服务不可用。

### 证据

- 错误态截图：`research/target-dongzheng-ai/screenshots/v1.0.0_20261118/02-对话/step05_历史服务异常态.png`
- 成功态截图：`research/target-dongzheng-ai/screenshots/v1.0.0_20261118/02-对话/step04_回复_行情K线与来源.png`
- 成功态界面树：`research/target-dongzheng-ai/ui-hierarchy/v1.0.0_20261118/02-对话/step04_回复_无障碍树缺正文.xml`
- 2026-11-18 5 次冷启动复测：`research/target-dongzheng-ai/logs/v1.0.0_20261118/ai-trials/20261118_122610/contact_sheet.png`

### 建议排查顺序

1. 记录失败请求的 Request ID、上游 HTTP 状态、首 token 时间、流式结束状态和超时时间。
2. 区分冷启动首问、切换网络后首问、普通连续提问三类场景，分别统计成功率。
3. 检查冷启动时的鉴权/token 初始化、AI 网关连接池、SSE/WebSocket 首包、模型路由和行情工具调用是否竞争资源。
4. 增加指数退避重试、幂等请求、会话恢复和“保留问题重新发送”按钮。
5. 定义最低可观测字段：`session_id`、`request_id`、`intent`、`model`、`tool_calls`、`first_token_ms`、`total_ms`、`error_code`、`retry_count`。

### 验收标准

- 连续 20 次冷启动首问中成功率 ≥ 99%，或在失败时 100% 展示可重试的结构化错误。
- 任何“服务开小差了”都必须可追溯到请求 ID 和上游错误码。

## DEF-002：AI 回复正文不进入无障碍/自动化界面树

### 复现步骤

1. 冷启动掌小宝，进入顶部「对话」。
2. 输入 `600519` 并发送，等待出现完整行情、K 线、文字结论、来源和推荐追问。
3. 保持页面不动，执行 `adb shell uiautomator dump /sdcard/window.xml`。
4. 导出 XML，并分别核对：顶部导航、输入框、AI 正文、来源、推荐追问、免责声明。

### 实际结果

- 截图可见完整的 AI 回复正文和 K 线卡片。
- 导出的界面树仅约 37 个节点，只包含「盯盘/对话/自选」「提问或搜索」「以上内容由AI生成，不构成投资建议」等少量文字。
- `600519` 回复正文、来源标题、推荐追问均未进入界面树。
- 对比测试中：
  - 同花顺问财：约 702 个节点，AI 正文进入界面树。
  - 国泰海通灵犀：约 367 个节点，AI 正文和引用进入界面树。
  - 涨乐财富通 Yomi：约 108 个节点，AI 投资结论进入界面树。
  - 长小牛 AI：约 24 个节点，AI 正文同样未进入界面树；说明该问题并非掌小宝独有，但仍是重要的无障碍与自动化风险。

### 影响

- TalkBack/读屏用户可能只能读到导航和免责声明，无法读取核心投资信息。
- UI 自动化、视觉回归和质量平台无法通过文本定位回复内容，只能依赖截图/OCR。
- 若后续接入投顾合规留痕、内容审核或答案抽检，自动化成本会显著增加。

### 当前结论边界

UIAutomator 界面树与 TalkBack 使用同一 AccessibilityNodeInfo 体系但并不完全等价。当前结论是“自动化无障碍树缺失”，不能替代真实的 TalkBack 口述测试。建议由测试同学在开启 TalkBack 后复测；若同样不可读，应升级为发布阻断缺陷。

### 建议修复

1. 为 AI 回复容器、标题、正文段落、来源卡片、推荐追问分别设置可访问文本或虚拟节点。
2. 流式输出时避免整块自绘；对增量文本使用 `liveRegion` 或等价的无障碍动态播报策略。
3. K 线等图片提供简短替代文本，例如“贵州茅台日 K，最新价 1457.70 元，涨跌 +0.26%”。
4. 对复制、点赞、重试、收藏等图标按钮补充 `contentDescription`。
5. 建立 TalkBack 回归用例：首问、流式生成、完成态、错误态、长回答滚动、来源打开。

### 证据

- `research/target-dongzheng-ai/screenshots/v1.0.0_20261118/02-对话/step04_回复_行情K线与来源.png`
- `research/target-dongzheng-ai/ui-hierarchy/v1.0.0_20261118/02-对话/step04_回复_无障碍树缺正文.xml`
- 竞品对照目录：`research/competitors/`

## PERF-001：冷启动首屏慢，骨架屏持续时间较长

### 复现步骤

1. 对 App 执行 force-stop，等待 1 秒。
2. 记录 `am start -W` 的输出和总耗时。
3. 从启动后立即开始连续截图：0、1、2、3、5、8、12、20 秒。
4. 标记四个时间点：
   - Activity 首帧时间；
   - 首页骨架屏出现时间；
   - 行情数字首次出现时间；
   - 页面主要模块稳定时间。

### 实测结果

- 2026-11-18 12:17 冷启动：`am start -W` 返回 `TotalTime: 2.064s`。
- 3.00 秒截图：首页已出现，但行情、成交额、涨跌家数仍为占位符/空值，板块异动为空。
- 3.68 秒截图：主要行情数字和板块异动开始出现。
- 4.48 秒及以后：视觉上基本稳定。
- 因此“系统认为 Activity 已启动”与“用户看到可用内容”之间存在约 1.5–2.5 秒的感知差。

### 风险解释

- 骨架屏本身不是错误，但若缺少进度提示、分段加载或缓存命中策略，用户会感知为“一直在转圈”。
- 首页同时存在行情、成交额、板块异动、榜单等模块；当前看起来接近同时请求、同时等待，未做明显的首屏分层。
- 网络切换、后台进程冷启动、系统低内存回收时，耗时可能显著拉长，用户主观感受与单次 `am start -W` 不一致。

### 建议

1. 将首屏拆为 P0/P1/P2 三层：先出指数与自选，再出板块异动/榜单，最后出个性化内容。
2. 使用上次成功数据做 stale-while-revalidate，明确标注“缓存数据/更新时间”。
3. 对每个模块单独设置超时、失败占位和重试，不要阻塞整页。
4. 预初始化网络/图片/WebView，但避免首页无必要地创建多个 WebView。
5. 增加启动性能埋点：`Application onCreate`、首帧、首网络响应、首内容渲染、完全可交互。
6. 在弱网、飞行模式切换、后台 24 小时、低电量模式下重复测试。

### 建议目标

- 中端测试机冷启动首内容 P90 ≤ 2.5 秒。
- 首页主要行情模块 P90 ≤ 3 秒。
- 冷启动失败时 1 秒内展示明确的加载状态和重试入口。

## PERF-002：重路径遍历后出现约 588 MB PSS 与 4 个 WebView

### 已观测数据

| 场景 | PSS | RSS | Activities | WebViews | Views |
|---|---:|---:|---:|---:|---:|
| 冷启动 6 秒 | 347,368 KB | 562,404 KB | 1 | 1 | 28 |
| 冷启动 12 秒 | 293,820 KB | 509,780 KB | 1 | 1 | 28 |
| 个股详情基础页 | 284,842 KB | 500,584 KB | 1 | 1 | 28 |
| 个股切换多标签后 | 407,006 KB | 632,600 KB | 3 | 1 | 494 |
| 第 2 轮 | 412,966 KB | 640,524 KB | 5 | 1 | 956 |
| 第 3 轮 | 528,346 KB | 756,040 KB | 5 | 1 | 956 |
| 第 4 轮 | 524,719 KB | 753,072 KB | 5 | 1 | 956 |
| 返回首页 20 秒 | 492,658 KB | 721,448 KB | 3 | 1 | 490 |
| 返回首页 80 秒 | 330,710 KB | 559,500 KB | 1 | 1 | 28 |
| 历史峰值 | **588,110 KB** | **742,676 KB** | **6** | **4** | **976** |

### 如何复现高风险峰值

1. 冷启动掌小宝。
2. 搜索并打开 `600519` 贵州茅台个股详情。
3. 依次切换「分时 / 日K / 周K / 月K」。
4. 查看「明细 / 大单 / 五档」。
5. 向下滚动，依次切换「看点 / 资讯 / 资金 / 基金 / 简况F10」。
6. 返回首页，再重复第 2–5 步 3–4 轮。
7. 在每个阶段执行 `adb shell dumpsys meminfo dongzheng.ai.android.phone`，记录 `TOTAL PSS`、`Activities`、`Views`、`WebViews`。
8. 同时执行 `adb shell dumpsys activity exit-info`，核对是否出现 `LowMem`、`LowMemQuick` 或系统杀进程记录。

### 系统退出记录

- 2026-11-17 11:42：`LowMemQuick`，主进程 RSS 约 344 MB。
- 2026-11-17 12:28：`LowMem`，主进程 RSS 约 197 MB。
- 2026-11-17 15:23：用户从最近任务上划，主进程 RSS 约 510 MB、pushservice 约 165 MB、WebView 沙箱进程约 186 MB 均退出。

### 结论边界

- 从第 2 轮到第 4 轮，PSS 从约 413 MB 升到约 528 MB 后基本持平，暂不能据此认定为“持续泄漏”。
- 返回首页后 20 秒仍有约 493 MB，80 秒后回落到约 331 MB，说明大量页面/图表/WebView 资源释放存在延迟。
- 目前更稳妥的结论是：**存在高风险峰值内存和释放滞后，叠加系统 LowMem 记录；需要继续排查 WebView、图表、Activity/View 引用和图片缓存。**
- 不应把一次遍历后的 588 MB 单独作为线上崩溃率证据。

### 建议排查

1. 每次进入个股详情时检查 Activity 实例数、View 树节点数和 WebView 创建数是否可收敛。
2. 对 K 线/图表/资讯/资金/基金模块做懒加载和离开页面后的资源回收。
3. 使用 Android Studio Memory Profiler 抓取 heap dump，检查 Activity/Fragment/WebView/图片缓存引用链。
4. 对同一路径连续 10 轮采样，观察 PSS、Native Heap、Java Heap、Graphics、WebView 数量是否单调上升。
5. 在低内存设备或模拟 `adb shell am send-trim-memory` 场景下验证回收策略。

## 已撤回：自选空态“点击语义不一致”

原记录认为“点击添加自选股”打开“新建分组”。复测后确认这是误判：

- 自选页顶部 `+` 的功能是「新建分组」。
- 列表下方「添加股票」的功能是进入股票搜索页。
- 从干净状态点击「添加股票」已正确进入搜索页，界面树与截图一致。

证据：`research/target-dongzheng-ai/screenshots/v1.0.0_20261118/03-自选/step03_点击添加股票_进入搜索.png`

因此该条不应进入缺陷清单。


## 附：UIAutomator 界面树是什么

界面树不是截图，也不是 logcat 日志，而是 Android 从当前页面提取出的控件结构。它包含控件类型、文本、描述、点击状态、坐标和层级。

本次现象是：截图能看到 AI 正文，但界面树只有导航、输入框和免责声明。因此对普通视力用户不一定可见，但对自动化测试、无障碍读屏和后续内容质检是真实风险。详细解释见 `technical-concepts.md`。
