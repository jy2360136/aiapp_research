# 掌小宝内存与首屏性能说明

## 1. 先说结论

1. **从最近任务划掉 App 后是否还占内存，取决于系统是否真的杀死进程。**
   - 仅按 Home、切到后台：进程通常继续驻留，占内存且可能被系统冻结。
   - 从最近任务上划：多数情况下会移除任务；部分厂商会立即杀进程，部分厂商会保留进程或后台服务。
   - 在“设置 → 应用 → 强行停止”或 `am force-stop`：进程一定会被杀，且 App 进入 stopped 状态，直到用户再次主动打开。
2. **本次荣耀测试机上，从最近任务上划后，主进程确实退出。**
   - 主进程 PID 变为空；
   - 主进程约 510 MB、pushservice 约 165 MB、WebView 沙箱进程约 186 MB 都记录为用户请求退出；
   - 再次打开是新 PID，属于冷启动。
3. **“进程退出”不等于“系统总内存立即下降”。**
   - App 私有内存会释放；
   - 页面缓存、文件缓存、系统共享库、GPU 缓存、ZRAM 等可能仍占用；
   - 系统通常不会为了“看起来内存下降”而主动清空所有缓存。
4. **掌小宝当前有真实的高内存峰值风险，但还不能直接判定为持续泄漏。**
   - 历史峰值：PSS 约 588 MB、RSS 约 743 MB、4 个 WebView、6 个 Activity、976 个 View。
   - 另一条个股详情路径中，PSS 从约 413 MB 上升到约 528 MB 后持平，未出现每轮持续增长；但返回首页后 20 秒仍约 493 MB，80 秒后回落到约 331 MB，属于“高占用 + 释放滞后”。
5. **首屏慢已复现。**
   - `am start -W` 约 2.1 秒返回，但 3.0 秒仍看到骨架屏和空数据；
   - 约 3.7 秒出现主要行情；
   - 约 4.5 秒视觉上基本稳定。
   - 用户看到“一直在转圈”，很可能来自 Activity 已启动但数据模块仍未完成加载。

## 2. 关键术语

- **PSS**：按共享页比例分摊后的进程内存，Android 常用它评估单 App 的近似占用。
- **RSS**：进程实际驻留的物理内存，会重复计算共享页，通常高于 PSS。
- **Java Heap**：Java/Kotlin 对象堆。
- **Native Heap**：C/C++/Native 库分配的内存。
- **Graphics**：图形缓冲区，图表、动画、图片多时容易上升。
- **WebView**：内嵌浏览器实例；每个实例都可能带来 Chromium 渲染进程、缓存和 GPU 资源。
- **Activity/View 数**：页面和 UI 控件数量。数量没有绝对标准，但重路径中错误堆积会让遍历、布局和回收成本上升。

## 3. 冷启动实测

### 3.1 采集方式

```powershell
python automation/startup_capture.py --label cold_start_retest --intervals "0,1,2,3,5,8,12,20"
```

脚本先 force-stop，再调用 `am start -W`，并在目标时间点截图。

### 3.2 结果

| 时间点 | 画面状态 |
|---|---|
| `am start -W` 返回 2.064 秒 | Activity 已报告启动成功 |
| 3.00 秒 | 顶部框架已出现，行情数字、成交额、涨跌家数、板块异动仍为空/占位 |
| 3.68 秒 | 主要指数、成交额、涨跌家数、板块异动开始出现 |
| 4.48 秒 | 首页视觉上基本稳定 |
| 5.99–20.78 秒 | 无进一步明显首屏变化 |

证据目录：`research/target-dongzheng-ai/screenshots/v1.0.0_20261118/01-盯盘/`，冷启动关键帧为 `step01`–`step03`

### 3.3 为什么“启动耗时 2 秒”和“用户觉得慢”可以同时成立

`am start -W` 衡量的是系统层面的 Activity 启动返回时间，不等同于：

- 所有网络请求完成；
- 首屏图表绘制完成；
- 用户最关心的行情、涨跌家数、板块异动可见；
- 页面已经可以稳定交互。

建议产品验收不要只看 `am start -W`，而要看“首内容时间”和“主要模块可用时间”。

## 5. 如何区分“高占用”与“内存泄漏”

至少看四个指标：

1. **基线**：冷启动首页稳定后的 PSS。
2. **峰值**：打开个股、图表、资讯、基金等重页面后的最高 PSS。
3. **回落**：返回首页 30 秒、60 秒、120 秒后的 PSS。
4. **趋势**：同一路径重复 5–10 轮，PSS、Native Heap、Graphics、WebView 数量是否持续单调上升。

当前结果：

- 峰值高：是。
- 回落慢：是。
- 持续单调增长：现有样本不完全支持。
- 与系统 LowMem 有关联：是。

因此建议缺陷标题使用“高风险峰值内存/释放滞后”，不要直接写“确认内存泄漏”。在拿到 heap dump 引用链之前，不能把责任唯一归因给某个 WebView 或图表组件。

## 7. 建议的性能预算

以下是产品侧建议，不是行业硬标准：

| 指标 | MVP 目标 | 优化目标 |
|---|---:|---:|
| 首页首内容 P90 | ≤ 2.5 秒 | ≤ 1.8 秒 |
| 首页主要行情模块 P90 | ≤ 3.0 秒 | ≤ 2.2 秒 |
| 首页稳定 PSS | ≤ 300 MB | ≤ 250 MB |
| 重路径峰值 PSS | ≤ 450 MB | ≤ 380 MB |
| 10 轮重复路径 PSS 增长 | ≤ 5% | 无可复现增长 |
| WebView 实例 | ≤ 2 | ≤ 1（按业务必需例外） |
| 返回首页 60 秒 PSS | 接近基线 + 50 MB | 接近基线 |

实际预算应基于目标机型分档：低端机、中端机、旗舰机分别设定。

## 8. 产品与研发动作

### 产品动作

- 首屏按优先级分层：指数/自选 → 板块异动 → 榜单/个性化内容。
- 加载超过 1.5 秒显示明确进度与阶段文案，而不是只给空白骨架。
- 局部失败不影响全局，单模块提供重试。
- 加入“上次更新时间”和缓存数据标识。

### 研发动作

- 记录启动、首帧、首网络响应、首内容渲染、可交互时间。
- 监控首页与重路径的 PSS、Native Heap、Graphics、Activity、View、WebView。
- 对 WebView 做池化或复用检查；页面退出后主动释放。
- 检查图表、图片、资讯列表的缓存上限和引用释放。
- 弱网、后台 24 小时、低内存、冷启动首问场景纳入发版回归。
